# 06 – Internationalisation

> The predecessor showed `Biomüll` to a user who had just arrived in Germany and
> could not read it. That is the bug this whole project exists to fix.

---

## 1. Principle

**Everything the user reads is in their language. The only exception is the word
printed on the physical bin – and that always appears with its translation.**

A user standing in front of a bin needs two things at once: to match the German
word they can see on the lid, and to know what it means. Showing only the
translation makes the physical object unmatchable. Showing only the German
reproduces the original problem. So: both, always, with clear visual hierarchy
between them.

```
┌──────────────────────────────────┐
│  Paper & cardboard               │  ← the user's language, primary
│  Papiertonne                     │  ← what's written on the bin, secondary
└──────────────────────────────────┘
```

## 2. Launch locales

| Locale | Script | Direction | Rationale |
|---|---|---|---|
| `en` | Latin | LTR | fallback and source of truth |
| `de` | Latin | LTR | the covered jurisdiction |
| `uk` | Cyrillic | LTR | large recent-arrival population in DE |
| `ru` | Cyrillic | LTR | widely used second language across the same group |
| `tr` | Latin | LTR | largest established migrant community in DE |
| `ar` | Arabic | **RTL** | large recent-arrival population; forces real RTL support at v1 |
| `es` | Latin | LTR | large student population |
| `fr` | Latin | LTR | large student population |
| `hi` | Devanagari | LTR | large student population; forces non-Latin metrics at v1 |

Arabic, Hindi and Ukrainian are in the **v1** set on purpose. A layout that only
ever had to hold English and German will break the first time it meets RTL or
Devanagari line heights, and it is far cheaper to design for that now than to
retrofit. This is a hard requirement on the design brief.

## 3. Why translations are static

Everything the user reads comes from a **closed vocabulary**, resolved at build
time into static JSON. Nothing is translated at runtime.

| | Static bundles (chosen) | Runtime LLM translation (rejected) |
|---|---|---|
| Cost | €0 | per scan, per language, forever |
| Offline | works | fails |
| Latency | 0 ms | 300–2000 ms |
| Determinism | identical for every user | varies run to run |
| Reviewability | a native speaker can proofread the file | unreviewable |
| Safety | a wrong string is fixed once, for everyone | wrong every time, differently |

The last two rows are the decisive ones. This app tells people what is safe to
put where. Advice that is non-deterministic and unreviewable is not acceptable,
regardless of cost.

## 4. What bounds the cost

The taxonomy's closed item vocabulary
([02-waste-taxonomy § 3](02-waste-taxonomy.md#3-the-closed-item-vocabulary)):

| Category | Count |
|---|---|
| Item ids (`newspapers`, `bioplastic_bags`, …) | ~130 |
| Stream names + notes | ~42 |
| Form factors | ~10 |
| Families | 6 |
| UI chrome, errors, onboarding, a11y labels | ~200 |
| **Total** | **~390 strings** |

× 9 locales = **~3 500 strings, translated once.** That is one bounded piece of
work, reviewable by a human per language, shipped as ~25 KB gzipped per locale.

New content enters through exactly two doors, both of which have a translation
step *before* publication:

- A new canonical item or stream → CI fails until every locale has the key.
- A new region pack → its `local_name`s are proper nouns and are not translated;
  its `note_key`s must resolve in every locale.

**A locale can never be partially shipped.** `scripts/validate_taxonomy.py`
fails the build on any missing key. There is no silent fallback to English in
production, because a half-translated safety instruction is worse than an
honestly untranslated one.

## 5. Implementation

- Bundles at `web/src/i18n/<locale>.json`, flat dot-namespaced keys
  (`stream.paper`, `item.newspapers`, `ui.scan.hint`).
- Loaded on demand, cached in IndexedDB with the region pack. Switching language
  offline works if the bundle was fetched; otherwise the UI says so plainly.
- Locale detection: explicit user choice → `navigator.languages` → `en`. The
  choice is offered in the first screen and is always one tap away, because the
  people who need it most cannot read the settings label in the default language.
  The language switcher is therefore rendered with **flags-free, endonym labels**
  (`Deutsch`, `العربية`, `Українська`) – never translated names, never flags.
- RTL via logical CSS properties throughout (`margin-inline-start`, not
  `margin-left`) and `dir` on `<html>`. No physical-direction properties anywhere
  in the design system.
- Numbers, dates, distances and relative times through `Intl`. Never hand-formatted.

## 6. Non-goals

- Translating user-submitted free text. Contributions are structured (form
  factor, colour, count, access) precisely so that nothing typed by a user needs
  translation, moderation for language, or safety review.
- Machine-translating region packs. `local_name` is a proper noun on a physical
  object; translating it would break the matching task it exists for.
- Auto-detecting language from GPS. Where someone is says nothing about what
  they read – and assuming otherwise is exactly the mistake this app corrects.
